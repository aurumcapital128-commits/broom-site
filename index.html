The watchdog

A skill can't watch your disk at 3 AM. A native process can.

Free cleanup scripts and agent skills only run when something invokes them, they burn tokens while they do, and when the disk fills and the agent dies, they die with it. Broom's watchdog is a native process, so it costs zero tokens and it keeps standing when everything else falls over.

01 — MEASURE

It watches the rate, not just the number

Free space per volume, and how fast it is dropping. A disk at 40% that is losing 100 GB an hour is an emergency; a disk at 15% that hasn't moved in a week is not.

02 — WARN EARLY

Before the wall, not after

If the current rate would cross the critical threshold in under two hours, you hear about it while the run can still be saved. The documented failures were silent; this one is not.

03 — KEEP SCORE

Every warning is counted

Warnings are logged and persist across runs, so after a month you can see exactly what the watchdog caught. It observes and warns by default; it never cleans anything without you.

The cleanup, when you ask for it

You review the plan before anything gets deleted

01 — SCAN

Deterministic scanning

Broom classifies files using fixed rules based on known paths, age and size. No LLM ever decides what's safe to delete, and every finding shows the exact rule that flagged it.

02 — REVIEW

You approve the plan first

A dry-run shows exactly what would happen before anything does. Your settings, skills and memory are always excluded automatically.

03 — RECLAIM

Undo for 7 days, logged forever

Files go to Broom's own trash instead of being deleted outright. One command restores everything, and you can ask broom explain about any past action at any time.

Questions

Before you hand Broom your disk

Does an AI decide what gets deleted? +

No. Classification uses deterministic rules based on known paths, age and size. An LLM is never in the delete path. At most, it drafts a plain-language explanation of a decision a rule already made.

What if Broom is wrong about something? +

Nothing is ever deleted directly. Everything goes to Broom's own trash with a manifest first, restorable byte-for-byte for 7 days. A circuit breaker also aborts and auto-restores if a cleanup deviates more than 20% from what the dry-run promised.

Can Broom run while my agents are working? +

That's what the Pro monitor is for: it watches disk pressure in the background and warns you before a long overnight run hits a full disk and dies. Cleanup itself never happens behind your back. It only runs when you, or a schedule you set, trigger it, and always against a plan you can dry-run first.

Do you collect telemetry? +

None by default. No usage data leaves your machine unless you explicitly opt in to something we document first. This is a disk tool for people who already don't trust software with their files.

What platforms are supported? +

Windows first, including native WSL2 virtual-disk compaction, because it's the least-served platform for this problem. macOS is next in line, and waitlist signups are how we decide how soon. Linux devs already live in a terminal, so for them the CLI version will do the job.
